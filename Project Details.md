# Project 6: Malaria Cell Detection & Explainable Computer Vision

1. Business / Real-World Problem Create a computer-vision screening prototype for educational/research use. The goal is not clinical diagnosis; it is to demonstrate a rigorous image-classification workflow, comparison of classical ML and DL, and explainability.
2. Dataset & Data Sources • Malaria Cell Images Dataset — Kaggle: Open dataset / source — 27,558 cell images in infected/uninfected folders; source acknowledgement points to NIH. • NIH Malaria Datasets: Open dataset / source — Primary source reference for the dataset family.
3. Core Objectives • Inspect class balance and image quality. • Create reproducible train/validation/test splits. • Perform image preprocessing and augmentation. • Build a classical ML image baseline using handcrafted features. • Build a CNN/transfer-learning model. • Perform error analysis by image characteristics. • Build an image-upload application.
4. Machine Learning Track — Required 55. Baseline: resize images + HOG/color/texture features + SVM or Random Forest. 56. Evaluate classical feature-based pipeline. 57. Build a confusion matrix and per-class metrics. 58. Document the limits of handcrafted features.
5. Deep Learning Track — Required Upgrade 59. Custom CNN baseline. 60. Transfer learning with a modern pretrained CNN such as EfficientNet/ResNet. 61. Data augmentation. 62. Class weights if needed. 63. Early stopping and learning-rate scheduling. 64. Compare custom CNN vs transfer learning. 65. Grad-CAM or similar visual explanation.
6. Advanced / Distinction Features • Test-time augmentation. • Calibration of predicted probabilities. • Robustness testing under blur/brightness/rotation. • Optional ensemble of two CNN models. • Optional segmentation/preprocessing extension if a suitable mask dataset is added.
7. Deployment & MLOps • Streamlit image upload UI. • Display predicted class + confidence + explanation heatmap. • Store inference logs without storing sensitive user information. • Version model and preprocessing pipeline.
9. Required Final Deliverables • Data preparation notebook. • Classical ML baseline. • CNN model. • Transfer-learning model. • Grad-CAM visualizations. • Robustness tests. • Streamlit demo. • Final report with responsible-AI section.
10. Evaluation & Success Criteria • Accuracy is insufficient alone. • Report precision, recall, F1, ROC-AUC, PR-AUC and confusion matrix. • Focus on sensitivity/recall for the infected class while explaining trade-offs.
11. Common Risks / Quality Checks • Do not present the system as clinical diagnosis. • Check for data leakage caused by duplicated/near-duplicated images. • Document dataset license and provenance.
